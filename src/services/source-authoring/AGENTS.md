# Directory rules
- AI Builder saves to source projects (imported or Affinity-written) re-check candidates with `sourceProjectApplySettings`: same alias/dependency rules as the Composer, no Unison preflight rewrites or Unison-lane repair, and edit scope = the edited page plus `sourceProjectEditTargets` plus new files. Why: the host re-check used Unison rules and the active tab, so valid source edits were rewritten or refused after the AI wrote them.
- The Builder connector only validates `/src/` targets for source projects (root files like `package.json` are still sent to the Composer). Why: its `/src/`-only check threw on `package.json` and stopped every imported-project AI edit before the AI was called.
- Source-project composer paths allow framework route names (`$param`, `[slug]`, `(group)`, `@slot`), root config/plugin files and source-folder JSON (asset pointers); `aiRepairLoop` resends a source-project edit once in the previous edge contract (no `sourceProject`, `/src` targets only) when the edge refuses the request shape. Why: an edge not yet redeployed refused every imported-project edit.
- New Affinity sites save as `affinity-authored`; if the live save rule refuses that label (pre-`20261112090000` database), `createAffinitySourceProject` relabels the draft and provenance `external-import` with `authoredBy: 'affinity'` and saves the same files once more. Why: an undeployed migration must not throw away a finished site.
