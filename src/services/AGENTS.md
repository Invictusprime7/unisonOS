# Directory rules
- Native submission CTAs focus their registered form rather than sending empty payloads; booking requires validity, deduplication and explicit backend success, and runtime sessions are site-scoped. Why: preserve site-host ownership and never imply an unconfirmed enquiry or booking.
- Project-list refreshes use serial coalescing with a trailing read; draft lookup projects only identity/name fields. Why: event bursts and embedded snapshots must not multiply list traffic.
- Live Demo uses accountDemoGeneration reservations; canonical revision operation IDs settle usage atomically. Why: browser flags cannot enforce an account allowance or prove a saved draft.
- App Builder candidate gates validate arbitrary CSS class values before acceptance; table recipes render scalar display values and bind only explicit source tables plus persisted row IDs. Why: syntax-valid JSX can still fail CSS compilation or render record objects as children.
- Portable recipe context projects App Builder's hash-verified materialization manifest; section IDs and canonical functional instance IDs stay separate. Auth forms own submit dispatch and local toggles own state. Why: names alone cannot prove executable exports or event ownership.
- The canonical revision RPC is guarded by a per-draft persist circuit breaker in `vfsCommitService.ts` (identical failed payloads back off 2s→60s; background saves never overlap an in-flight write); why: a re-firing failing save once flooded the database with ~80 failed writes per second.
- User-driven Builder edits (`ai-builder`, `playground-edit`) run preflight with `allowQuarantine: false` and `closeRequiredIntents: false`; why: an unparseable page must reject the edit instead of committing a stub, and intent closure once injected forms into unrelated pages during style edits.
- Scoped Builder guards detect copy/side effects outside the request or clicked element (`builder/scopedEditContentGuard.ts`); Mixed/Review can hold these for approval, while Full Auto bypasses advisory holds but keeps canonical validation and destination checks; why: permission behavior must stay explicit without removing save invariants.
- Automated sync sources (binding-fast-path, ghl-binding, republish) are refused by `commitMutation` when their base revision predates the newest committed ai-builder revision; why: legacy sync must never overwrite a saved AI change.
- Live Preview renders live VFS bytes: `snapshotProjector` lets every live `/src/**` byte and addition win over the sealed snapshot whatever its origin (embedded or navigation state), keeping the snapshot byte only for placeholder stubs or an `index.css` that lost its theme tokens; why: snapshot copies lag saves, and Unison snapshot sections were replacing AI-authored custom TSX.
- Draft hydration self-heals a missing/invalid `last_revision_id` read-only from the newest non-empty committed revision of the same draft only; why: a lost pointer once blanked a project that still owned saved revisions.
- `commitMutation` refuses to persist a revision that drops a non-empty `/src/App.tsx` present in its parent unless `explicitAuthorityReset` is set; why: blank saves must never become the accepted revision.
- Playground "Manage → Assets" is a read-only projection (`resources/assetCatalog.ts`) over the Resource Runtime; launch seeds planned catalog items/business details once via `resources/seedLaunchAssets.ts`. Why: one editor path, no parallel asset store.
- Article/case-study pages are built deterministically by `resources/longformPages.ts` and committed with an `add_page` route op; why: AI-prompted page creation timed out on large sites.
- Backend per site is chosen only by `project-backend/projectBackendResolver.ts`; catalog/content rows carry `project_id`, written and filtered by `cms-records`/`site-runtime-read`. Why: sites under one business must not share saved items.
- Editing surfaces issue `EditorCommand`s via `editor/editorCommandService.ts`, routed per property to ResourceRuntime or host `commitMutation` executors. Why: one editing protocol, no parallel writer.
- Preview selection identity comes from `editor/editableObjectDescriptor.ts` (resource mark → source locator + instance index → unbound); reacquire matches exact objectId only. Why: guessing the first matching JSX tag edited the wrong repeated card.
- Builder saves (toolbar, terminal, AI, autosave) share one queue in `builder/builderMutationCoordinator.ts` (autosave pause, fingerprint rebase of non-overlapping AI candidates; `aiApplyGate` keeps the strict stale check) with a per-surface stall budget, and preview verification runs after the queue is released; why: one never-settling save blocked every later save for hours, so edits were never written and no checkpoints existed.
- The durable draft queue rebases file edits by exact bytes and typed edits by captured domain dependencies, advancing candidate lineage; reviewed artifacts and genuine overlaps refuse. Why: unrelated saves must not block page, theme or composition edits.
- Code-terminal file commands emit FileOps to `onPatch` and the host commits them via `commitBuilderFiles` inside `runExclusive('terminal')`; the terminal never writes the VFS itself. Why: the old `onWriteFile` → `importFiles` path bypassed save, checkpoints and the coordinator.
- ResourceRegistry derives Records groups, aliases and creation defaults from schemas; historical type IDs remain readable. Editor and preview adoption share resourceIdentity over scoped rows and reject ambiguity. Why: no duplicate records or guessed writes.
- Generation loads CMS schemas for its contract project without mutating the UI registry; seeding preserves owner media from the scoped inventory and normalizes billing intervals. Explicit catalog targets beat industry defaults; cart needs priced registry intents and a checkout projection. Why: no cross-site context or invented payment support.
- Dedicated publication checks accepted component reads and saved resource marks through the same read-only gateway schema probe used by CRUD. Why: ready connection details do not prove usable resource tables.
- Site-profile override updates compare the read JSON inside the write; missing rows insert without upsert. Why: concurrent edits must not silently overwrite another site's saved details.
- PlaygroundSyncController is hydration-only; inferred compatibility hydration cannot dirty a clean draft. Preserve explicit topology edits and canonical launch compilation. Why: read-back must never become a competing source save.
- Project lists (Home, Cloud) rank a project whose draft has no accepted revision by its creation time, never updated_at; why: maintenance writes bump empty shells above real saved work.
- Projects with no saved version or source, older than 1 hour, are deleted by the owner-scoped `cleanup_empty_projects()` RPC on Home load; why: empty shells cluttered project lists.
- One lead form per page: a rendered certified Contact design (default or named import) is the registered contact host and counts as its native form; materializer and required-intent closure never add a second lead form, and closure inserts inside <main>. Native field keys derive from labels (fieldId on collision; saved fieldId keys still validate). Why: generated IDs showed as captions and platform forms duplicated design forms, sometimes after the footer.
- Builder source edits and page repairs fail the `data-honesty` gate when they drop a visible "Sample data" label the base file showed, unless the instruction is about that label or real data. Why: a live AI edit silently removed the label, making demo scores read as real.
- Industry vertical knowledge for every website use case lives as data packs in `composition/verticals/`; it feeds detection, owner-named interaction requirements, inferred pages for unnamed multi-page requests, composition profiles (only when the industry has none), design ranking and an advisory brief block, and never provisions capabilities. The launch seals industry + vertical into the creative brief's `site`, which the builder connector projects (trade knowledge, copy depth, photo library) into every later edit and added page; packed whole-block, never tail-cut. Why: industries differ by data, and enrichment re-guessed from short edit instructions thinned out after launch.
- Owner-named pages come from the prompt, single "X page" phrases, short feature lists and Affinity's confirmed summary bullets, mapped through pack page vocabulary (`matchVerticalPageName`) or kept as custom routes; everyday-word aliases (help, work, updates…) count only beside "page", and inferred pages never replace named ones. Why: "Help me…" planned an FAQ while RSVP, releases and tour dates were dropped.
- External imports (`src/services/import/`) run secure intake → compatibility profile → one `commitMutation` under the `imported-source` profile: source bytes and assets stay unchanged, `/.unison-import/` records are read-only, and no Unison compiler/router/theme stage runs over them. Preview runs only through a source-compatible adapter resolved live by `resolveImportPreviewAdapter` (static HTML: original bytes in an opaque-origin frame, only local references resolved at serve time); everything else shows the blocked status, and publish stays blocked until parity is recorded. Chat drops and the Import button share `importExternalProject` + `importHandoff`. Why: imports were being rewritten into Unison designs.
