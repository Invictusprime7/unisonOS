# Architecture decisions
- GitHub Vercel deployment uses `vercel pull` → `vercel build` → `vercel deploy --prebuilt` with explicit credentials; push and manual runs deploy main only. Why: use Vercel's environment and avoid rebuilding checked output during deployment.
- Unset Babel breaking mode: browser.
- Load Unison tokens last; hero effects opt in via theme bridge. Why: protect vendor skins.
- Demo counts settle with canonical revisions. Why: count only saved generations.

- New projects start only in the Affinity chat: `PromptLaunchPanel` runs `runLaunchPipeline` with `buildPromptLaunchInput` and never authors or mutates VFS; the guided Wizard, its saved interview drafts and step markers are deleted, and project import lives in the panel. Why: one creation surface and one launch path.
- `UnisonAppBuilder` is the sole fresh-launch application author; `generate-page` reuses Composer and saved Home design. Why: no parallel writer.
- The canonical platform owns topology/routes, capabilities/intents/bindings, Theme/Stage 4b tokens, Art Direction, UI foundation, protected infrastructure and validation; never generate competing pages after App Builder authorship.
- `commitMutation` remains the only legal canonical writer; initial generation accepts one passing candidate, never repairs or per-page checkpoints as revisions.
- Saved revisions hydrate read-only; role recovery uses explicit role/type before shared route aliases (Visit → contact), preserving source. Candidates stay unsanitized/unsplit; uploads/images survive repairs. Why: preserve saved work and valid page types.
- Composer contracts mirror `supabase/functions/_shared/aiComposerContract.ts` and `src/contracts/aiComposerContract.ts`; enforce targets/routes/import reads/intents; prefer hunks, accept replaces. Why: vocabulary is not readiness.
- Composer modes stay in `ai-code-assistant/composerLane.ts`. Why: no parallel author/repair/edit pipelines.
- Page composition intelligence lives in `src/services/composition/` (one universal planner + data-only industry profiles, consumed under App Builder orchestration); why: industries differ by data, never by engine.
- Generic composition profiles inherit by role identity, not array position; design-source role filtering uses the composition role normalizer, and unsupported families are corrected in profile inputs before sealing, never removed from sealed targets. Why: shifted profiles and legacy role spellings requested sections the canonical page contract could not execute.
- Variant selection goes through `src/services/designImplementationEligibility.ts`; variants carry authored `capabilities`/`compatibility`/`lifecycle`/`ai` contracts, preferred over string inference. Why: registry growth narrows candidates deterministically, never widens AI context.
- Composer page context is packed by priority in `app-builder/contextBudget.ts`; prop contracts ride early in runtimeContext and whatever exceeds its cap continues as `overflow` in the page brief, never cut. Each family gets several seed-ranked variants; Contact hosts the registered form. Why: the cap cut prop contracts and form rules, giving bare sections and stray forms.
- WebBuilder launch-handoff dedupes on `routeHandoffImportedRef`, never `importedRouteStateRef`; why: revision adoption updates the shared ref, replaying original Wizard files over saved edits.
- `projects` ↔ `builder_drafts` name-sync triggers skip when `pg_trigger_depth() > 1` and write only changed values; why: re-entry raises SQLSTATE 27000 and blocks saves.
- Persist draft chat in owner-only `builder_chat_history` via debounced `aiHistoryStore.setMessages`; localStorage is a cache. Why: chats survive devices.
- Both modes enforce sealed section order/archetypes; AI requires every requested page authored. Starter variants use legal pins, geometry and seed. Why: prevent sparse pages and baseline-as-AI acceptance.
- Live-VFS commits absorb pending ops recorded before capture and advance the autosave baseline; pending ops conflict only off another base revision. Why: lagging baselines raised false conflicts.

- The owner's prompt leads every brief; `launch/creativePlan.ts` projects never-truncated requirement IDs and a design direction (explicit → confirmed → labelled provisional); requests carry one mirrored `PROMPT_CREATIVE_AUTHORITY_POLICY`. Why: registry-only rules and silent Modern defaults flattened prompts.
- Flagged `launch/authorshipTrace.ts` records hashes/paths/counts per build stage; `firstLossBoundary` names where authored modules vanish. Why: locate authorship loss in one run.
- Agent tools use enforced dispatch; proposals use `runBuilderAiMutation` → `commitMutation`. Capture live VFS/revision together; refuse stale preparation/selection. Resolve prompted parts to visible-page source owners; refuse only incomplete target reads. Why: guessed pages changed unrelated content.
- Direct preview edits prefer exact source-locator spans and restrict writes to the clicked owner; structural actions share the toolbar save path. Inspector family recovery uses registered variants/slots and live composition. Why: runtime selectors and active-page-only deletes missed imported sections or edited lookalikes.
- Toolbar executors follow property-owner routing: JSX move/delete/duplicate use source, styling and visibility use presentation. Why: a presentation-only move handler was unreachable and rejected every reorder before saving.

- Service/recipe rules: `src/services/AGENTS.md`; provider rules: `supabase/functions/_shared/AGENTS.md`; marketplace rules: `src/marketplace/AGENTS.md`.
- App Builder enforces its provider contract in the shared plan independently of stale client model overrides; the existing loop preserves direct-first and managed-backup execution. Why: runtime key presence must not authorize a different provider for template installation.
- When the owner's Gemini key reports depleted credits (402/quota-exhausted), the provider loop marks it on a 15-minute per-isolate cooldown and uses the direct Lovable AI gateway only when this project has its own `LOVABLE_API_KEY`; otherwise the App Builder reports provider failure. Why: never imply an unavailable fallback.
- Edge functions never import sibling function directories (only `_shared` is bundled); `generate-page` is a thin internal proxy to `ai-code-assistant` gated by the `x-unison-page-generation-only` header, and shared helpers live in `_shared`. Why: cross-function imports fail to bundle at deploy time.
- App Builder resolves optional owner AI preferences once at its facade for generation, page creation and edits, forwarding them through authoring and closure repair; marketplace inherits this facade without separate settings. Why: installation must use the same configuration as Affinity, while server provider policy remains authoritative.
- Contract binding derivation adopts the resolved registered component's write intent as the binding's coreIntent (industry recipes may name the business goal, e.g. lead.capture, while the contact form owns contact.submit). A failed page with no baseline source is terminal: authoring stops and diagnostics surface only that page's gate errors, never the downstream missing-file cascade. Why: intent drift permanently blocked closure, and continuing sibling pages burned credits on builds that could never close.
- UNISON is the only backend: `src/integrations/supabase/env.ts` ignores other injected refs, `main.tsx` fails closed on identity mismatch, and backend changes deploy only via `.github/workflows/supabase-auto-update.yml`, so every schema change needs a timestamped `supabase/migrations` file (drizzle alone fails CI); why: Lovable tooling targets its built-in database.
- Auth listeners stay synchronous; events win initial reads; SDK alone invalidates refresh; tab bridges yield to persisted auth; chunk retries are explicit. Auth/callbacks go Home or Demo; handoffs skip both and Auth. Why: avoid deadlocks, stale sign-out and reloads.
- Before app load, bridge only auth keys to sessionStorage on quota errors; never evict project data or edit the generated client. Why: full storage must not block sign-in; fallback lasts until the tab closes.

- Builder preferences are optional local state enforced at request/execution boundaries; tools gate the menu, catalog/business settings gate their operations. Why: hiding controls cannot authorize disabled mutations.

- Records use EditorCommand/adapter writes; generation schemas are job-scoped. Why: prevent cross-site leakage.
- CMS create/update supplies the full audited/idempotent RPC signature, including null workflow target; transitions alone set a target status. Why: PostgREST resolves functions by their complete named arguments.
- Edit gates retain compile/imports, ownership, protected paths, data-loss and binding safety; design/scope is advisory. Queue rebase checks domain dependencies, not age; reviews remain revision-bound. Why: independent saves must not block edits.

- Affinity shows public paragraphs, never native thinking. Why: explanations without private deliberation.
- Launch progress projects canonical stage and page/batch events into a bounded public activity feed; elapsed time never advances completion. Why: visitors can see real work without fabricated progress or private reasoning.
- Published cart intents use the canonical client commerce adapter with site-scoped browser persistence and quantity badges; checkout stays server-priced and provider-gated. Why: a bag can persist without granting payment authority or trusting browser prices for charges.
- App Builder checks contracts before/after source-owned repairs; provisioning and cosmetic repetition are draft advisories, never paid repairs. Active ownership, render safety and publish gates remain enforced. Why: save usable designs without costly full-page rework.
- Composer fix rounds send candidate source only in FILES (previousResponse lists paths), and an interrupted fix round resumes from its accumulated draft rather than re-authoring the page. Why: duplicated source made fix rounds time out and every from-scratch retry re-billed the full page.
- App Builder uses two-section batches, complete-source fileOps (server applies EDIT), preservation checks and exact-request tab checkpoints; retries resume failed work, never accept partial revisions. Normalize operation labels; corrections need a full window. Default one page worker; budgets cover all batches. Provider loop honors Gemini cooldowns once if time fits, never retries billing/timeouts. Why: prevent quota bursts, lost paid work and nested retries.
- The Lovable AI gateway is an optional direct fallback only when the project configures its own `LOVABLE_API_KEY`; never relay requests through another project's function or shared secret.
- App Builder carries selected fields/site-owned references; native-form rules: src/services/AGENTS.md. Unhandled intent-exec actions fail via _shared/unsupportedIntent.ts, never acknowledge success. Why: preserve host ownership and avoid false submissions.
- Provisional pages use canonical component/binding/composition materializers; Home must pass before later pages read its source/sidecar and object references, never its authorization. Why: inherit wired objects without accepting partial revisions.
- Affinity Graphics (`src/services/graphic-design/`) keeps one whole-document model: AI create/edit replies pass `normalizeGraphicDocument`, edits send image tokens instead of image data, and canvas, design check and exports render from the same document via `graphicRenderer.ts`; the backend `affinity-graphic-design` leads with Gemini and uses only a directly configured gateway backup. Why: no parallel canvas writer, and photo data never inflates or gets rewritten by AI turns.
- Conversational design choices are read only by `launch/experienceDirector.ts` into `experienceDirection`, sealed as design-selection pins and `/.unison/creative-brief.json`; edits refine it in their own commit. Why: Wizard picks survive as owner words, never a second planner/writer.
- External imports (`src/services/import/`) run secure intake → compatibility profile → one `commitMutation` under the `imported-source` profile: source bytes and assets are kept unchanged, `/.unison-import/` records are read-only, no Unison compiler/router/theme/preview stage runs over them, and Preview/publish stay blocked until a source-compatible isolated runtime proves parity. Why: imports were being rewritten into Unison designs.
