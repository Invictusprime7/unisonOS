# Shared edge rules
- Gemini is the primary text provider across shared Edge Function clients and `providerRouter`: when configured, direct Gemini always runs first; other configured direct providers follow as fallbacks, and Lovable is last. App Builder page writing, repair and Builder source edits use a budgeted Gemini-first plan, then configured OpenAI, then Lovable; explicit `AI_PROVIDER_MODE=gemini-only` still opts out of direct fallbacks. Why: unfunded fallback providers masked template install failures; owner chose Gemini priority on 2026-10-24.
- Direct-Gemini composition leads with Gemini 3.8 Flash (`composerGeminiModel` in `_shared/providerRouter.ts`, mirrored in `runDirectGemini`), overridable by the `GEMINI_COMPOSER_MODEL` secret; OpenAI and Lovable provide provider-level fallback rather than an older Gemini model.

- `AI_PROVIDER_MODE=gemini-primary` makes Gemini priority explicit; weighted distributions and explicit model selections must not move another provider ahead of configured Gemini. Lovable can never lead while any direct provider is configured. `GEMINI_COMPOSER_MODEL` controls composition; `GEMINI_MODEL` is the default for unspecified Gemini calls and must not replace explicit fallback model IDs.
- App Builder authoring splits the request window between Gemini and configured OpenAI, preserving the remaining window for Lovable. Do not cache timeouts to change priority on later turns; each request starts with the configured primary.
- Builder source edits return SEARCH/REPLACE `<<<EDIT` blocks that `composerLane.ts` applies to the request's FILES before validation. Why: rewriting whole files produced 20–30k-token answers that outran the ~122 s provider window.
- Builder source edits must use `<<<EDIT` hunks on existing files (FILE replace/create on an existing path is rejected in `composerLane.ts`); page-creation requests may only create new pages plus nav/footer edits, and read only the target + site chrome; scoped client reads skip transitive imports, theme and package files unless the instruction names them. Why: whole-file rewrites and bloated context outran the provider window.
