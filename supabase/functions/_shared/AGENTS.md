# Shared edge rules
- App Builder page writing, repair and Builder source edits run Gemini-only (`ProviderPlan.geminiOnly` set in `_shared/providerRouter.ts`, honored in `_shared/aiProviderLoop.ts`): direct Gemini API leads, Gemini on the managed gateway is the only backup; no OpenAI/Anthropic attempts. Why: an unfunded OpenAI key failed and masked template installs; owner chose Gemini on 2026-10-24.
- Direct-Gemini composition leads with Gemini 3.8 Flash (`composerGeminiModel` in `_shared/providerRouter.ts`, mirrored in `runDirectGemini`), overridable by the `GEMINI_COMPOSER_MODEL` secret; OpenAI and Lovable provide provider-level fallback rather than an older Gemini model.

- Gemini service configuration (2026-10-06): AI_PROVIDER_MODE=gemini-primary explicitly leads launch and builder composition with funded Gemini 3.8 Flash, retaining configured OpenAI and Lovable as fallbacks. Hybrid mode retains the managed-gateway lead described above. GEMINI_COMPOSER_MODEL controls composition; GEMINI_MODEL is the default for unspecified Gemini calls and must not replace explicit fallback model IDs.
- After a direct Gemini attempt times out, the managed gateway leads composer turns with the full window for 10 minutes (per isolate). Why: a timed-out Gemini lead left the gateway only the deadline tail, so every fallback also timed out.
- Builder source edits return SEARCH/REPLACE `<<<EDIT` blocks that `composerLane.ts` applies to the request's FILES before validation. Why: rewriting whole files produced 20–30k-token answers that outran the ~122 s provider window.
- Builder source edits must use `<<<EDIT` hunks on existing files (FILE replace/create on an existing path is rejected in `composerLane.ts`); page-creation requests may only create new pages plus nav/footer edits, and read only the target + site chrome; scoped client reads skip transitive imports, theme and package files unless the instruction names them. Why: whole-file rewrites and bloated context outran the provider window.
